# IL 학습 방법 정리 (IL run 11 기준, 2026-11-24)

IL run 11에 적용된 방법과 제한, 그렇게 정한 이유, 시험했지만 넣지 않은 것을 한곳에 정리한 문서입니다.
명령과 도구 사용법은 [`TOOLS.md`](TOOLS.md), 날짜별 결과 기록은 [`TRAINING_S2R.md`](TRAINING_S2R.md)에 있습니다.

- **IL의 목표**: 적당히 빠르게, **안정적으로** 완주합니다. 극한의 랩 타임은 PPO가 맡습니다.
- **해결해야 할 문제**: 넓은 막다른 공간으로 들어가 충돌, 직진 비틀거림, 출발 직후 실패, 느린 주행.
- 표의 "도입"은 해당 내용이 처음 들어간 시점입니다. run 7 = 11/17, run 8 = 11/19~21, 11/23 = 실차 보정, run 9·10 = 11/23, run 11 = 11/24.

## 6. run 11에서 고친 시뮬레이터 조향 버그

- **문제**: 중간 조향 비율(`steer_scale`)을 끝까지 꺾을 때도 곱하고 있었습니다. 그래서 왼쪽 기준값 0.85에서 **왼쪽 최대가 0.35 rad**였습니다(실차는 0.41 rad). 정책은 시뮬레이터에서 "왼쪽은 더 꺾어야 한다"를 배우게 되고, 실차에서는 왼쪽으로 과하게 꺾어 흔들릴 위험이 있었습니다.
- **수정**: 실제 바퀴 각도 = 명령 × (k + (1 − k) × x²)입니다. 여기서 x는 |명령| / 0.41입니다. 중간 영역은 k배만큼 꺾이고, 끝까지 꺾으면 정확히 명령 그대로 0.41 rad가 됩니다.
- **비율 값**: 좌우 대칭 0.85~1.05로 바꿨습니다. 11/23의 "왼쪽 0.75~0.8"은 주행 로그 한 번에서 나온 추정이었고, 원선회 측정은 좌우가 같았습니다.
- **효과**: expert가 가장 나쁜 조건에서 일반 트랙 79.5 % → 87.9 %로 올라갔습니다.

## 7. expert (IL이 따라 하는 대상, `utils/rule_based.py` RacelinePlanner)

| 기능 | 내용 | 도입 |
|---|---|---|
| 경로 추종 | 레이스 라인 pure pursuit. 앞을 보는 거리 = 0.6 m + 0.22 × 속도 | run 7 |
| 지연 보정 | 이미 보냈지만 아직 적용되지 않은 명령으로 미래 위치를 예측하고, 그 위치 기준으로 조향 | run 7 |
| 속도표 | 레이스 라인 곡률 기반. 코너와 제동은 **그 에피소드 μ의 60 %**, 가속은 차 한계까지. 코너 앞에서 미리 감속 | run 7, μ 비례는 11/23 |
| 라인 합류 | 라인에서 0.6 m 이상 벗어나면 2 m/s 쪽으로 감속하며 합류 | run 7 |
| **꺾는 동안 가속 제한 (`hold`)** | 지금 조향으로 접지 70 %를 넘는 속도라면 더 가속하지 않음. 조향 때문에 감속하지는 않음. 기준 속도는 조향 0.2 rad에서 2.4 m/s, 0.1에서 3.4, 0.05에서 4.8, 0.02에서 7.6 m/s | **run 10** (run 9는 "꺾는 만큼 감속") |
| 속도 상한 | 에피소드 상한 안에서 계획 | run 7 |
| 성능 (혼자 2랩, 고친 조향) | 일반 100 %, 막다른 공간 96.6 %, 가장 나쁜 조건 87.9 % / 80.7 %. 2랩 평균 약 156 s | |

## 12. 시험했지만 넣지 않은 것 (11/23~24, 평가와 데이터 분석 기준)

| 방법 | 결과 | 판단 |
|---|---|---|
| expert "꺾는 만큼 감속" (`cap`, run 9) | 정책이 흔들리는 상태에서 정답의 34 %를 감속 정답으로 만들어, 랩이 두 배 느려짐 | `hold`로 교체 |

| 감속 규칙을 출발할 때만 (`start`) / 라인 밖에서만 (`hold_off`) 적용 | 막다른 공간 87~89 % | `hold`가 더 안정적이고 느리지도 않음 |
| lookahead 늘리기 (기본값 1.0·1.4 m, 계수 0.30·0.35, 라인 밖에서만 +0.8 m/m) | 정답은 부드러워지지만 expert가 코너 안쪽을 깎아 성공률 52~98 %로 하락, 3~5 s 느려짐 | 0.6 + 0.22 × 속도 유지 |

| Huber 오차 함수 | 큰 조향을 덜 배우는 문제를 악화시킴 | MSE 유지 |
| CAPS spatial 0.1, 과거 명령에 잡음, 신경망 폭 1024 | 짧은 행동 복제 확인에서 효과 없음 | 넣지 않음 |

## 13. run 9 / run 10에서 확인된 원인 (분석 요약)

- **run 9**: 라운드 3에서 일반 73.5 %, 막다른 공간 43.2 %. 랩이 약 2배 느렸고, 떨림은 expert의 약 10배였습니다.
  - 감속 정답 문제(위 12장 첫 줄)가 있었습니다.
  - 정책이 큰 조향이 필요한 곳에서 필요한 조향의 35~60 %만 꺾었습니다(주 실패 원인).
  - 직진 근처에서는 방향 일치가 64 %로, 사실상 잡음처럼 떨렸습니다.
  - 학습 오차와 검증 오차가 함께 높았습니다. 정답을 관측으로 맞추기 어렵다는 뜻입니다. 조향 지연과 μ처럼 정책이 볼 수 없는 정보는 그중 약 13 %이고, 나머지는 정책이 레이스 라인 위치를 볼 수 없는 탓으로 추정합니다.
- **run 10**: 라운드 3에서 일반 82.6 %, 막다른 공간 39.8 %로 run 9보다 일반이 9 %p 높았습니다. 6장의 조향 버그를 발견해 라운드 4에서 중단하고 run 11로 다시 시작했습니다.

## 14. 남은 과제

- **실차 가감속 측정**: `tools/speed_test.py --speed 5.0` 후 `tools/drive_session.sh --finish --speed`. 측정값은 PPO `--sim_override`의 `sim2real.a_max`에 넣습니다. 제동이 가속과 많이 다르면 시뮬레이터에서 둘을 분리해야 합니다.
- **큰 조향에서 덜 꺾는 경향**이 남으면 PPO에서 개선합니다.
- **대회 맵 도구**는 차가 트랙을 잘 돌게 된 뒤에 만듭니다. 원본 LiDAR 전부 사용, 1 m/s 이하, 6~8 m 이내 값, 2~3바퀴, 5 cm 격자로 계획되어 있습니다.
- **PPO**: 보상은 진행 거리 − 시간, 충돌 −200, 조향 급변·벽 여유·접지 한계 벌점입니다. 모델 선택은 짝지은 랩 타임, 최악 조건, 막다른 공간 기준이고, 설정은 `TRAINING_S2R.md`와 `TOOLS.md`에 있습니다. IL 결과를 보고 파라미터를 정한 뒤 시작합니다.
