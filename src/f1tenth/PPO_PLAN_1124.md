# PPO 계획: 보상 설계와 진행 방법 (2026-11-24)

IL(run 11) 다음 단계인 PPO 미세조정의 보상, 안정성을 지키는 장치, 진행 순서, 결과를 보고 조정할 기준을 정리했습니다.
IL에 적용한 방법은 [`IL_METHODS_1124.md`](IL_METHODS_1124.md), 명령과 옵션은 [`TOOLS.md`](TOOLS.md) 3장에 있습니다.

**목표**: 안정적으로 완주하면서, 그 안에서 최대한 빠르게.
IL은 "적당히 빠르게, 안정적으로" 도는 데까지만 하고, 랩 타임 단축은 PPO가 맡습니다.

## 1. 보상 (매 스텝 0.025 s)

구현 위치는 `utils/env.py`의 `calc_reward`이고, 계수는 `train_ppo_s2r.py` 옵션으로 바꿉니다.

```
보상 = 10 × 진행 거리[m]                          ← 트랙 중앙선을 따라 앞으로 간 거리 (뒤로 가면 마이너스)
     − 0.1                                        ← 시간 벌점 (스텝마다)
     − 3 × (조향 명령 변화량)²                     ← 조향 급변(흔들림) 벌점, 정규화된 명령 기준
     − 5 × max(0, 0.30 − 가장 가까운 벽 거리)       ← 벽 여유 벌점 (LiDAR 기준 0.30 m ≈ 차체 옆 0.15 m)
     − 2 × max(0, |횡가속도| − 0.8 × μ × 9.81)      ← 접지 한계 벌점 (expert는 접지 60 %로 주행)
     − 500 (충돌 시, 에피소드 종료)                 ← 충돌 벌점 (PPO 1은 200 → 완주율 하락, 아래 3장)
     + 2 × max(0, 기준 랩 타임 − 이번 랩 타임)       ← 랩 보너스 (기본 꺼짐: --lap_bonus 2로 켬)
```

| 항목 | 옵션 (기본값) | 목적 | 설계 이유 |
|---|---|---|---|
| 진행 거리 | `--progress_coeff 10` | 주 신호 | 빨리 달릴수록 스텝당 보상이 커짐 |
| 시간 벌점 | `--time_cost 0.1` | 랩 타임 최소화 | 2랩 거리는 정해져 있어서, 총 보상 = 고정값 − 4 × (2랩 시간[s]). **1 s 빨라지면 +4.** 최저 속도 0.5 m/s의 진행 보상(0.125/스텝)보다 작아야 한다는 조건은 코드가 검사함 |
| 조향 급변 | `--steer_rate_cost 3` | 직진 흔들림 억제 | 제곱이라 서보 속도에 맞춰 나눠 꺾으면 거의 깎이지 않음. 좌우로 반복하는 떨림만 누적해서 깎음. expert의 급코너 주행에서 전체 보상의 0.1 % |
| 벽 여유 | `--wall_cost 5`, `--wall_margin 0.30` | 실차 안전 여유 | |
| 접지 한계 | `--lat_cost 2`, `--lat_grip_share 0.8` | 미끄러짐 방지 | expert(60 %)보다 공격적으로 코너를 돌 여지를 줌 |
| 충돌 | `--collision_cost 500` | 박지 않기 | 2랩 시간 125 s어치 (PPO 1의 200은 부족했음) |
| 랩 보너스 | `--lap_bonus 0` | 추가 속도 자극 | 시간 벌점과 목적이 겹치고 신호가 드물어 꺼 둠 |

**보상 크기 점검** (expert 2랩 주행에 기본 계수 적용, 11/23)

| 항목 | 스텝당 평균 | 진행 보상 대비 |
|---|---|---|
| 진행 보상 | +1.37 | |
| 시간 벌점 | −0.10 | 7.3 % |
| 조향 급변, 벽 여유, 접지 한계 | 각각 −0.005 이하 | 각각 0.3 % 이하 |

잘 달리는 주행에는 안전 벌점이 거의 붙지 않습니다. 흔들리는 정책으로 짧게 시험했을 때는 접지 벌점이 스텝당 −0.7~−1.5까지 커져, 무리한 주행을 억제하는 것을 확인했습니다.

**보상 처리**
- 누적 보상의 표준편차로 나눠 정규화합니다(`--ret_norm 1`).
- 2랩을 완주하면 성공으로 처리하고 충돌과 달리 "끝"으로 끊지 않습니다(시간 초과처럼 이어서 계산).

## 2. 안정성을 지키는 장치

보상만으로는 안정성을 보장할 수 없습니다. 기대 보상으로 보면 "1 s 빨라지는 대신 충돌 확률 2 % 증가"가 손익이 비슷해서, 보상만 보면 정책이 위험을 쉽게 받아들일 수 있습니다. 그래서 **모델 저장 기준**이 안전장치 역할을 합니다. 아래 네 가지를 모두 만족해야 저장됩니다.

1. 일반 트랙 2랩 완주율이 지금까지 최고 모델 이상
2. 둘 다 완주한 주행끼리 비교한 랩 타임이 더 빠름 (짝지은 비교)
3. 가장 나쁜 조건(지연 0.2 s, μ 0.4, 가속 2.5, 조향 비율 하한, 노이즈 2배) 완주율이 IL 이상
4. 큰 막다른 공간 시험 트랙 2랩 완주율이 IL 이상

이 밖에 다음 장치가 있습니다.
- **IL 쪽으로 당기는 힘**: 0.5에서 0.02까지 줄어들고, 평가 완주율이 IL보다 2 %p 떨어지면 다시 2배로 올립니다.
- **critic 먼저 학습**: critic이 보상의 60 % 이상을 설명할 때까지 actor를 고정합니다(최대 20 업데이트).
- **한 번에 조금씩만 변경**: clip 0.15, KL 0.015를 넘으면 그 업데이트를 중단합니다.
- **탐색 노이즈**: 조향은 작게(표준편차 0.10 → 0.06), 속도는 크게(0.22 → 0.14) 시작해서 학습하며 줄입니다.
- **속도 상한 없는 에피소드 50 %**: 대회 8 m/s를 대비합니다.

**한계**
- PPO는 IL 정책 근처에서 더 나은 해를 찾는 방식이라, 가장 좋은 랩 타임을 보장하지는 않습니다.
- 안전 여유(접지 80 %, 벽 0.3 m)는 일부러 랩 타임을 조금 포기하는 설정입니다.
- 시뮬레이터의 최대 가감속과 접지는 아직 정확하지 않아서, 최종 판단은 실차 주행으로 합니다.

## 3. 진행 순서

1. **IL run 11 결과 확인**. PPO 시작 조건은 일반 98 %, 막다른 공간 95 %. IL이 더 개선되지 않는데 기준에 못 미치면 `--force_start`로 시작합니다.
2. **PPO 학습** (기본 보상, seed 1, IL 기준 미달이라 `--force_start`):
   ```bash
   OMP_NUM_THREADS=1 nohup ~/venv/f1tenth/bin/python -u train_ppo_s2r.py --il imitation/11 --algo_idx 2 --force_start \
       > results/ppo_2_train.log 2>&1 &
   # 실차에서 측정한 가감속이 있으면: --sim_override 측정값.yaml (sim2real.a_max)
   # 중간에 멈췄으면 같은 명령에 --resume
   ```
   주행용 프로세스 16개와 평가용 8개가 기본입니다(이 PC 메모리 기준).
3. **시뮬레이터 분석**:
   ```bash
   python plot_training.py ppo_s2r/2                              # 학습 곡선
   python -u compare_models.py imitation/11 ppo_s2r/2 expert            # 완주율, 최악 조건, 막다른 공간, 짝지은 랩 타임
   python plot_failures.py ppo_s2r/2 --tracks open:big            # 막다른 공간 실패 장면
   ```
4. **모델 보관**: `results/ppo_s2r/2/{sim2real,backup}`을 `git add -f`하고 태그 `model-il11-ppo2`을 붙입니다.
5. **실차 시험**. 아래 4장을 따릅니다.
6. **조정**: 아래 5장 기준으로 한 번에 하나씩 고치고 PPO를 다시 돌립니다. 개선이 보이면 seed 2로 재현을 확인합니다.

### PPO 1 설정 (11/24, IL run 11 결과 기준으로 기본값 변경)
| 항목 | 이전 → 지금 | 이유 |
|---|---|---|
| `--total_steps` | 6M → 12M | IL이 98 %가 아닌 88 %에서 시작해 고칠 것이 많음. 학습률·당기는 힘·노이즈도 이 길이에 맞춰 천천히 줄어듦. 예상 5~6시간(평가 포함) |
| `--bc_start` | 1.0 → 0.5 | BC 대상이 IL 정책 자체라, 강하게 당기면 IL의 급코너 덜 꺾음(필요량의 31~43 %)까지 붙잡음. 완주율이 IL보다 떨어지면 2배로 올리는 장치는 유지 |
| `--log_std_steer` | −2.5 → −2.3 | 급코너에서 더 꺾는 쪽을 찾게 탐색 폭을 조금 키움 (0.034 → 0.041 rad). 지연 때문에 크게는 안 올림 |
| `--bc_speed` (새 옵션) | 1 → 0.25 | IL은 일부러 적당히 빠르게(평균 3.5 m/s, 2랩 199 s vs expert 156 s) 만든 정책이라, 속도까지 IL로 당기면 랩 타임 단축을 막음. 조향은 그대로 당겨 안정성 유지 |
| `--track_focus` (새 옵션) | 균등 → 3 | 트랙 322개를 같은 확률로 뽑으면 대부분 이미 잘 도는 트랙. 최근 실패율이 높은 트랙(막다른 공간, 급코너)을 최대 4배 자주 뽑음. 전체 실패율로 당겨서 주행 몇 번으로 과하게 치우치지 않게 함 |
| `--stuck_time` 등 (새 옵션) | 없음 → 3 s / 0.5 m, 역주행 2 m | 막다른 공간에서 돌아 나오거나 역주행하면 시간 한도(1.6 m/s로 2랩)까지 의미 없이 달렸음. 충돌로 끝내 신호를 분명히 하고 주행 시간을 아낌. 평가는 원래 규칙 그대로 |
| `--full_eval` (새 옵션) | 매번 → 저장 후보일 때만 | 평가 1회 264번 주행(약 9분) × 27회 ≈ 4시간이 학습보다 길었음. 최악 조건·막다른 공간은 일반 평가에서 최고 이상인 모델만 저장될 수 있으니 그때만 실행. 저장 기준은 그대로 |
| 조향 급변 벌점 | 3 유지 | 올리면 급코너에서 빠르게 크게 꺾는 것도 막아 덜 꺾음 해결을 방해. 떨림이 남으면 다음 실행에서 올림 |

### PPO 1 결과 (11/24, 업데이트 50에서 중단)
| 평가 | 일반 2랩 완주율 | 둘 다 완주한 주행의 2랩 시간 |
|---|---|---|
| IL | 87.9 % | 기준 (평균 199 s) |
| 업데이트 10 / 20 / 30 / 40 | 65.9 / 57.6 / 56.8 / 50.8 % | 10.3 / 23.2 / 43.7 / 46.8 s 빠름 |

- 속도를 올리는 대신 완주율을 내줌(학습 주행 평균 속도 3.4 → 4.5 m/s, 완주 61 → 48 %). 저장된 모델 없음.
- 원인 1: γ 0.995(약 5 s 앞)로 보면 "10 % 빨라지는 대신 5 s마다 4~5 % 충돌 위험"이 손익 비슷 → 2랩 동안 쌓이면 완주율이 크게 떨어짐. 충돌 200이 작았음.
- 원인 2: 완주율이 떨어질 때 IL 쪽으로 당기는 힘을 2배씩 올리는 장치가 `bc_start`(0.5)를 넘지 못하게 되어 있어 초반에는 효과가 없었음(로그 bc_w 0.500 고정).
- 좋은 신호: 둘 다 완주한 주행은 최대 약 23 % 빨라짐 → 랩 타임을 줄일 여지는 큼. 조향 급변 벌점은 0.18 → 0.08로 줄어 떨림도 감소.

### PPO 2 설정 (PPO 1에서 바꾼 것)
| 항목 | PPO 1 → PPO 2 | 이유 |
|---|---|---|
| `--collision_cost` | 200 → 500 | 위험을 감수할 이득이 약 절반으로 줄어듦 (5장 기준표의 "충돌률 증가" 조정) |
| `--bc_max` (새 옵션) | 상한 = bc_start → bc_start × 8 | 완주율이 IL보다 2 %p 넘게 떨어지면 당기는 힘이 실제로 0.5 → 0.85 → 1.7 → 3.4로 커짐 |
| 나머지 | 같음 | 속도 당김 0.25는 랩 타임 목표 때문에 유지. 그래도 완주율이 안 지켜지면 다음에 올림 |

### PPO 2 중간 결과 (11/24, 진행 중)
| 평가 | 일반 2랩 완주율 | 둘 다 완주한 주행 |
|---|---|---|
| IL | 87.9 % | 기준 (199 s) |
| 업데이트 10 / 20 / 30 / 40 / 50 | 84.1 / 72.7 / 77.3 / 81.1 / 78.0 % | 10.8 / 18.6 / 28.6 / 33.8 / 27.9 s 빠름 |

- 충돌 500으로 PPO 1보다 안정적이고 약 15~17 % 빨라졌지만, 완주율이 78~81 %에서 멈춤.
- IL 쪽으로 당기는 힘이 상한(4.0)까지 올라감: 안전을 IL 흉내로 확보하는 구조라 라인·조향이 IL에 가깝게 묶임.
  목표(IL보다 모든 면에서 나은 RL)와 맞지 않음 → PPO 3.

### PPO 3 설정 (PPO 2에서 바꾼 것)
| 항목 | PPO 2 → PPO 3 | 이유 |
|---|---|---|
| 완주율이 IL보다 떨어질 때 | IL 쪽 당김 2배 (`--bc_adapt 1`) → **충돌 벌점 1.5배** (`--crash_adapt 1`, 최대 2000) | 안전을 IL 흉내가 아니라 보상으로 정책 스스로 배우게 함 (제약 강화학습 방식). IL 이상이면 0.8배씩 500까지 내림 |
| IL 쪽 당기는 힘 | 강화 장치로 최대 4.0 | 0.5 → 0.02로 줄어들기만 함 (초반 안정용) |
| 출발점 | IL | `--init`: PPO 2의 가장 좋았던 체크포인트 (업데이트 40: 81.1 %, 33.8 s 빠름). 확보한 속도 개선을 이어받음. 저장 기준은 계속 IL과 비교 |
| 충돌 벌점 목표 | — | **래칫** (`--crash_target best`): 저장된 최고 모델의 완주율(처음엔 IL 87.9 %)을 목표로, 올라가기만 함. IL을 넘기 전에는 IL 고정과 똑같이 동작하고, 넘은 뒤에도 완주율을 계속 끌어올림 |
| IL 기준 평가 | 매번 다시 (약 8분) | `--baseline_from ppo_s2r/2`로 PPO 2의 값을 재사용 |

```bash
OMP_NUM_THREADS=1 nohup ~/venv/f1tenth/bin/python -u train_ppo_s2r.py --il imitation/11 --algo_idx 3 --force_start \
    --init ppo_s2r/2/checkpoint/model_1760000.pt --baseline_from ppo_s2r/2 --crash_target best > results/ppo_3_train.log 2>&1 &
```
점검(학습 없음): 학습 프로세스 안에서 충돌 벌점이 500 → 750으로 바뀌고 충돌 보상에 반영됨, PPO 2 체크포인트 로드,
PPO 2의 IL 기준값(87.9 / 83.3 / 67.0 %, 199 s) 재사용 확인.

| 평가 | 전체 | 5 m/s | 8 m/s 중앙선 / 무작위 | 충돌 벌점 |
|---|---|---|---|---|

| 업데이트 10 | 84.8 % | 88.6 % (171 s) | 81.8 / 84.1 % (158 s) | 750 |

- 충돌 벌점 자동 조절로 8 m/s 붕괴(업데이트 20)는 회복했고, 완주한 주행은 8 m/s 2랩 143~149 s로 expert(약 156 s)보다 빠름.
- 하지만 80 % 근처에서 멈춤. **실패를 나눠 보면 평가 트랙 중 원본(깨끗한) 22개는 95~100 %, 학습에서 뺀 변형 w105 22개가 59~61 %.**
  IL도 실패 16번이 전부 w105 (원본 100 %, w105 76 %).
- 같은 방식으로 만든 변형 중 학습에 쓴 w104 vs 안 쓴 w105 (8 m/s 중앙선): IL 100 % vs 77 %, PPO 3 업데이트 40 82 % vs 45 %.
  → **본 트랙의 변형을 외우는 과적합이 주원인** (맵 23개 × 2방향 = 레이아웃 46가지, 각 5개 변형만 학습), 고속의 복잡한 트랙 자체의 어려움이 부원인.
  충돌 벌점(이미 상한)으로는 못 고침.

### PPO 4 설정 (PPO 3에서 바꾼 것)

### PPO 5 진행 (11/24, PPO 4 업데이트 40에서 시작, 어려운 조건 25 % + 막다른 공간 트랙 20 %)
| 평가 | 일반 2랩 완주율 | 둘 다 완주한 주행 |
|---|---|---|
| 업데이트 10 / 20 / 30 / 40 | 75.0 / 83.3 / 81.1 / 79.5 % | 52.2 / 45.3 / 49.5 / 50.1 s 빠름 |

- 학습 주행 충돌이 31 → 35 → 39 → 46 %로 늘고 속도는 유지: 충돌 벌점이 상한 2000에 묶임.
- 계산: 스텝당 보상 약 0.016(정규화), γ 0.995로 약 5 s 앞까지 봄, 충돌 손해 약 33 → "5 s마다 약 1 % 충돌 위험으로 10 % 빨라지기"가
  손익 같음 → 2랩(약 30구간) 동안 쌓이면 에피소드 충돌 약 26 %. 실제 학습 충돌 30~46 %와 맞음 = 보상이 정한 균형점.
  완주 95 %를 원하면 구간당 위험 0.17 % 이하 → 충돌 벌점 약 6배 필요.
- 조치: `--crash_max` 2000 → 10000 (기본값도 변경), 업데이트 40 상태의 벌점을 4000으로 올려 `--resume`.
- 막다른 공간에 직진할 때 받는 진행 보상: 정상 코너보다 약 27 % 적음(통로 밖은 마지막 1~2 m뿐). "통로 밖 진행 보상 0"은
  보상을 10 % 정도만 줄여 효과가 작아 넣지 않음.

### PPO 5 준비 (11/24)
PPO 4의 남은 약점(최악 조건, 막다른 공간)을 학습에서 더 자주 겪게 함. 둘 다 기본값은 꺼짐이고 PPO 5에서만 켬.

| 항목 | 내용 | 이유 |
|---|---|---|
| `--hard_prob 0.25` (`--hard_frac 0.4`) | 학습 에피소드 25 %에서 지연·접지·가속·조향 비율·노이즈를 **모두 동시에** 각 범위의 어려운 쪽 40 % 안에서 뽑음 | 따로 무작위로 뽑으면 나쁜 조건이 겹치는 경우가 거의 없음. 최악 조건 평가는 전부 겹친 경우 |
| `--open_train_share 0.2` | 학습 에피소드 20 %를 **막다른 공간 학습 트랙**(모든 코너에 큰 막다른 공간)에서 | 일반 학습 트랙에는 급코너 절반에만 작은 막다른 공간. 실차의 넓은 공간 문제와도 같은 종류 |
| 막다른 공간 학습 트랙 | `python -u eval_open_space.py --make_train`: 23개 맵 × 2방향 × 시드 200~203 = 184개 (200·201 = big 수준, 202·203 = train 수준), `installation/maps_open_train/` | 시험 트랙(시드 901·902)과 겹치지 않음 |

점검(학습 없음): 꺼져 있을 때 학습·평가·최악 조건 모드의 무작위 값이 이전 코드와 똑같음(평가 기준 유지),
어려운 에피소드 200개 모두 어려운 쪽 40 % 안, 막다른 공간 트랙이 실제로 20.2 % 뽑힘, 학습 프로세스에 설정 전달 확인.

```bash
OMP_NUM_THREADS=1 nohup ~/venv/f1tenth/bin/python -u train_ppo_s2r.py --il imitation/11 --algo_idx 5 --force_start \
    --init ppo_s2r/4/checkpoint/model_<가장 좋은 업데이트>.pt --baseline_from ppo_s2r/2 --crash_target best --crash_start 2000 \
    --hard_prob 0.25 --open_train_share 0.2 > results/ppo_5_train.log 2>&1 &
```

## 4. 실차 시험 방법

| 단계 | 방법 |
|---|---|
| 모델 선택 | IL만: `MODEL=il tools/drive_session.sh` / IL+PPO: `MODEL=ilppo tools/drive_session.sh` (`agent_ilppo.yaml`의 `algo_idx`를 저장된 PPO 번호로) |
| 속도 | `speed_limit` 3.0 → 5.0 → 대회 8.0 순서로 올림. `steer_gain` 1.0, `speed_min` 0 |
| 기록과 평가 | 주행 후 `tools/drive_session.sh --finish` → `tools/eval_drive.py` 결과(벽 접촉, 접촉 사이 거리, 속도, 흔들림)를 IL과 IL+PPO로 비교 |
| **가감속 측정** | `tools/speed_test.py --speed 5.0` (5~6 m/s) → `tools/drive_session.sh --finish --speed`. 측정값을 다음 PPO의 `sim2real.a_max`에 넣음. 제동이 가속과 많이 다르면 시뮬레이터에서 둘을 분리 |
| 막다른 공간 확인 | 문제가 났던 지점을 다시 주행하고, 로그로 그 지점의 LiDAR 값을 확인 (반사가 안 되는 벽이면 열린 공간으로 보임) |

|---|---|
